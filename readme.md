# 📜 Scraper судових рішень — lpd.court.gov.ua

Скрипт автоматично обходить базу правових позицій Верховного Суду України
та збирає структуровані дані про судові рішення з реєстру `reyestr.court.gov.ua`.

---

## 🎯 Результат

Фінальний `results.json` має вигляд:

```json
[
  {
    "caseNumber": "671/1486/17",
    "date": "30.10.2018",
    "url": "https://reyestr.court.gov.ua/Review/77285671"
  },
  {
    "caseNumber": "123/456/18",
    "date": "15.05.2019",
    "url": "https://reyestr.court.gov.ua/Review/..."
  }
]
```

---

## 🧠 Як це працює

Сайт `lpd.court.gov.ua` побудований на React (SPA), тому Фази 1 і 2
використовують справжній браузер **Chromium** у прихованому режимі.
Реєстр `reyestr.court.gov.ua` — звичайний HTML, тому Фаза 3 використовує
легкі HTTP-запити без браузера.

### Проблема з ID

URL документа виглядає так:
```
https://lpd.court.gov.ua/legal-position/{position_id}/document/{doc_id}
```

`position_id` і `doc_id` **не завжди однакові**. Наприклад:
- pos=**11** / doc=**5986**
- pos=**39** / doc=**39**
- pos=**41** / doc=**23**

Тому скрипт спочатку виявляє правильні пари ID, і лише потім обходить документи.

## 🔄 Три етапи роботи

```
┌─────────────────────────────────────────────────────────────────┐
│  ФАЗА 1  (Chromium)                                             │
│  /legal-position/1  →  doc_id: [1]                             │
│  /legal-position/2  →  doc_id: [2, 847]                        │
│  /legal-position/11 →  doc_id: [5986]                          │
│                         збереження → results_phase1.json        │
└──────────────────────────┬──────────────────────────────────────┘
                           │  пари (posId, docId)
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│  ФАЗА 2  (Chromium)                                             │
│  pos=2  / doc=847  →  🔗 reyestr.../Review/88776655            │
│  pos=11 / doc=5986 →  🔗 reyestr.../Review/77285671            │
│                         збереження → results_phase2.json        │
└──────────────────────────┬──────────────────────────────────────┘
                           │  унікальні URL реєстру
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│  ФАЗА 3  (HTTP, без браузера)                                   │
│  reyestr.../Review/77285671  →  № 671/1486/17  |  30.10.2018   │
│  reyestr.../Review/88776655  →  № 335/1893/16  |  15.11.2018   │
│                         збереження → results.json + .csv        │
└─────────────────────────────────────────────────────────────────┘
```

У Фазі 1 для пошуку `doc_id` використовуються три стратегії по черзі:
1. Посилання виду `/legal-position/{posId}/document/{docId}` у DOM
2. Будь-яке посилання з `/document/{число}` на сторінці
3. JSON-дані вбудовані у `<script>` теги (резервний варіант)

У Фазі 3 для пошуку номера справи та дати використовуються три варіанти парсингу:
1. `Категорія справи № X/Y/Z` у таблиці метаданих сторінки
2. `Справа № X/Y/Z` у тексті рішення
3. Перше число виду `ХХХ/ХХХХ/ХХ` на сторінці

## ⚙️ Встановлення

Потрібен **Node.js 18+**.

```bash
# Встановити залежності
npm install playwright

# Завантажити Chromium (один раз, ~150 МБ)
npx playwright install chromium
```

---

## 🚀 Запуск

### Найпростіший варіант (позиції 1–100):
```bash
node scraper.js
```

### З усіма параметрами:
```bash
node scraper.js --start 1 --end 3000 --concurrency 3 --registry-concurrency 8 --output results.json
```

---

## 📋 Параметри

| Параметр                  | Опис                                                  | За замовч.     |
|---------------------------|-------------------------------------------------------|----------------|
| `--start`                 | З якого `position_id` починати                        | `1`            |
| `--end`                   | До якого `position_id` (включно)                      | `100`          |
| `--concurrency`           | Паралельних вкладок Chromium (Фази 1 і 2)             | `3`            |
| `--registry-concurrency`  | Паралельних HTTP-запитів до реєстру (Фаза 3)          | `8`            |
| `--output`                | Назва фінального JSON-файлу                           | `results.json` |
| `--timeout`               | Таймаут на одну сторінку Chromium (мс)                | `15000`        |
| `--phase1-only`           | Зупинитись після Фази 1                               | —              |
| `--phase2-only`           | Зупинитись після Фази 2 (сирі посилання)              | —              |
| `--resume`                | Пропустити Фази 1–2, взяти посилання з `_phase2.json` | —              |

## 📂 Вихідні файли

### `results.json` — фінальний результат
```json
[
  {
    "caseNumber": "671/1486/17",
    "date": "30.10.2018",
    "url": "https://reyestr.court.gov.ua/Review/77285671"
  }
]
```
Містить лише успішно оброблені записи (статус `ok`).

### `results.csv` — таблиця з усіма записами
```
caseNumber,date,url,status,error
671/1486/17,30.10.2018,https://reyestr.../Review/77285671,ok,
```
BOM-маркер — відкривається в Excel без проблем з кирилицею.
Містить також записи з помилками для аналізу.

### `results_phase1.json` — проміжний: які doc_id знайдено
```json
[
  { "posId": 1,  "status": "ok",        "docIds": [1] },
  { "posId": 11, "status": "ok",        "docIds": [5986] },
  { "posId": 3,  "status": "not_found", "docIds": [] }
]
```

### `results_phase2.json` — проміжний: сирі посилання на реєстр
```json
[
  {
    "posId": 11, "docId": 5986,
    "status": "ok",
    "links": [
      { "href": "https://reyestr.court.gov.ua/Review/77285671", "text": "Переглянути" }
    ]
  }
]
```

## 📊 Статуси

### Фази 1 і 2 (консоль)

| Іконка | Статус      | Значення                                        |
|--------|-------------|-------------------------------------------------|
| ✅     | `ok`        | Знайдено дані                                   |
| 🔷     | `no_docs`   | Сторінка є, але документів не знайдено          |
| 🔶     | `no_links`  | Документ є, але посилань на реєстр немає        |
| ⬜     | `not_found` | Сторінка не існує                               |
| ❌     | `error`     | Помилка мережі або таймаут                      |

### Фаза 3 (реєстр)

| Іконка | Статус      | Значення                                        |
|--------|-------------|-------------------------------------------------|
| ✅     | `ok`        | Номер справи і дату успішно отримано            |
| ⬜     | `not_found` | Рішення в реєстрі не знайдено (404)             |
| ❌     | `error`     | Помилка мережі, таймаут або rate limit          |

## 💡 Практичні поради

### Скільки всього позицій на сайті?
Перевірте спочатку невеликим діапазоном з `--phase1-only`:
```bash
node scraper.js --start 1 --end 50 --phase1-only
```
Коли статуси `not_found` йдуть суцільним блоком — досягли кінця бази.

### Якщо скрипт впав посередині
Проміжні файли зберігаються автоматично після кожної фази.
Відновлення залежить від того, де впало:

```bash
# Впало у Фазі 3 — пропускаємо 1 і 2, беремо збережені посилання
node scraper.js --start 1 --end 3000 --resume

# Впало у Фазі 2 — пропускаємо тільки Фазу 1
node scraper.js --start 1 --end 3000 --phase1-only   # НЕ запускати
# (results_phase1.json вже є, просто запустіть без флагів з --resume)
node scraper.js --start 1 --end 3000 --resume
```

### Як не перевантажити сервери?
- Chromium (Фази 1–2): `--concurrency 3` — безпечно, 5 — нормально, 8+ — ризик блокування
- Реєстр (Фаза 3): `--registry-concurrency 8` — безпечно, скрипт автоматично додає затримку 200 мс між запитами і обробляє rate limit (429)

### Великий обхід (1000+ позицій)
Запускайте частинами, потім об'єднайте JSON-файли:
```bash
node scraper.js --start 1    --end 1000 --output part1.json
node scraper.js --start 1001 --end 2000 --output part2.json
node scraper.js --start 2001 --end 3000 --output part3.json
```
```javascript
// merge.js
const parts = ['part1.json','part2.json','part3.json'];
const all = parts.flatMap(f => require(`./${f}`));
require('fs').writeFileSync('merged.json', JSON.stringify(all, null, 2));
```

## 🛠️ Вимоги

- **Node.js** v18 або новіший
- **npm** пакети: `playwright` (вбудовані модулі `https`, `fs` — без додаткових залежностей)
- **ОС**: Windows, macOS, Linux
- **Місце на диску**: ~200 МБ для Chromium + місце під результати
